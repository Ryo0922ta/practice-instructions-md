## クリーンアーキテクチャを採用する場合の構成

以下のレイヤーに分割してください。

- controller（インターフェース層）
- usecase / service（アプリケーション層）
- domain（ドメイン層）
- infrastructure（データアクセス層）

依存関係は必ず以下を守ってください。

- controller → usecase → domain
- infrastructure → domain

※ domain は他レイヤーに依存しないこと。

## 必須条件
- ファイル単位で出力すること

- 各クラスの責務を明確にすること

## 禁止事項
- すべてを 1 クラスにまとめること
- ビジネスロジックを Controller に書くこと

## 実装詳細

### Controller
- REST API の定義のみに留めること
- ビジネスロジックは書かないこと

### UseCase / Service
- SQL 生成ロジックを実装すること
- ビジネスロジックの中心として設計すること

### Domain
- SQL 生成に関するモデルとルールを定義すること

### Infrastructure
- スキーマ取得処理を実装すること
- SQL 生成仕様に関わる外部アクセスを担当すること

## SQL 生成仕様
- PostgreSQL 構文で生成すること
- `SELECT *` を禁止すること
- `WHERE` 句は `AND` 結合を前提とすること
- 型に応じてクォートを適切に制御すること
- 出力対象は SQL 文のみにすること

## 品質要件
- 可読性の高いコードであること
- 命名は Java 標準に準拠すること
- 拡張しやすい構造にすること
- テストしやすい設計にすること

## 出力ゴール
- Spring Boot でそのまま動作する構成であること
- SQL 生成 API が機能する状態であること
- フロントエンドと接続可能な構成であること
- ユーザーが選択したアーキテクチャに厳密に従って出力すること
